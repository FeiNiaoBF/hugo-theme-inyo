# Inyo P1 Release Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the P1 correctness and accessibility gaps found in the Inyo theme CR while preserving the current paper/ink visual direction.

**Architecture:** Keep Hugo templates, one native CSS file, and the existing zero-runtime-dependency approach. Share summary-source extraction between catalog summaries and SEO metadata, use class-based Chroma output styled by the existing CSS tokens, and give taxonomy pages their own Hugo templates instead of forcing them through the article-list template.

**Tech Stack:** Hugo 0.140+, Hugo Modules, Go templates, native CSS variables, PowerShell verification script, existing exampleSite.

## Global Constraints

- Colors must come from `assets/css/main.css` tokens; any new color requires DESIGN.md documentation and WCAG contrast data.
- Every new style must provide light and dark values through `[data-theme="dark"]`.
- Body text, navigation, and footer remain horizontal; no `writing-mode: vertical-rl`.
- Runtime JavaScript remains limited to theme switching and the hover-gated Hero interaction; keep `hover:hover` and reduced-motion behavior.
- Do not add a frontend framework, CSS preprocessor, or runtime dependency.
- Do not modify or stage the existing `demo-shots/` artifacts as part of P1.
- Preserve the user’s current working-tree changes in `layouts/partials/summary.html` and `exampleSite/content/posts/theme-guide.md` while implementing the fixes.
- Verification must include `hugo --source exampleSite --minify`.

**Interfaces:**

- [ ] **Step 2: Add the verification script with explicit assertions**

The script must:

1. Build to a fresh temporary destination with `hugo --source exampleSite --minify --destination <temp>`.
2. Assert the build output contains `katex.min.css` for the article with `math: true`.
3. Assert article and home HTML contain `property=og:image` and `twitter:image`.
4. Assert `about/index.html` does not contain `article:published_time`.
5. Assert `posts/index.html` contains the localized heading `文章`, and `tags/index.html` contains `标签`.
6. Assert generated code blocks do not contain `background-color:#272822` or `color:#f8f8f2` inline styles.
7. Print the output directory and fail with a specific message for each failed assertion.

Use this shell shape so the script remains readable and does not depend on a test framework:

```powershell
$ErrorActionPreference = "Stop"
$out = Join-Path ([System.IO.Path]::GetTempPath()) "inyo-theme-verify-$PID"
hugo --source exampleSite --minify --destination $out

function Assert-Contains($Path, $Pattern, $Message) {
  $text = Get-Content -Raw $Path
  if ($text -notmatch $Pattern) { throw $Message }
}

function Assert-NotContains($Path, $Pattern, $Message) {
  $text = Get-Content -Raw $Path
  if ($text -match $Pattern) { throw $Message }
}
```

- [ ] **Step 3: Run the new checks and record the expected failures**

Run:

```powershell

```

Expected before fixes: failures for page-level math, missing default social image, article metadata on About, English taxonomy titles, and inline Chroma colors. Do not weaken assertions to make the baseline pass.
