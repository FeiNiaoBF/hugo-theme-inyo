我写长文时，最容易犯的错是把所有想到的东西都留在第一稿里。后来我给自己定了一个简单的顺序：先写摘要，再拆标题，最后才补链接和例子。页面看起来反而更安静，信息也没有少。

## 先写首页摘要

`description` 只要一句话，`summary` 可以把文章的来路和重点说完整。首页不需要显示整篇文章，只要让读者知道这篇内容值不值得打开。

```yaml
---
title: "一篇有清楚入口的文章"
description: "一句话说明文章主题。"
summary: "两句完整的导读，交代问题从哪里开始、文章准备走到哪里。读者在首页就能大致判断这是不是自己正在找的内容。"
---
```

摘要写完以后，正文第一段就不必重复介绍标题，可以直接进入故事或问题。

## 让标题承担导航

一节只做一件事。标题太多会把文章切碎，标题太少又会让读者迷路。我会先写一个只有标题的空骨架，再把相邻的段落放回合适的位置：

- 先说背景；
- 再给一个具体例子；
- 最后写我的判断或下一步。

需要回到某一节时，可以使用标题生成的锚点，也可以手动给标题加上稳定的 ID。这样以后修改段落，链接不会轻易失效。

## 用标记代替解释

小范围的任务清单比“接下来要做很多事情”更有用：

- [x] 写好文章摘要
- [x] 检查图片替代文本
- [ ] 发布前在暗色模式下读一遍

键盘操作也可以直接写在句子里：按下 <kbd>Ctrl</kbd> + <kbd>K</kbd> 打开链接编辑。行内代码适合表示文件名、参数和命令，例如 `hugo server --buildDrafts`。

## 链接要有边界

真正有用的链接应该出现在读者刚好需要它的地方：[Hugo 官方文档](https://gohugo.io/)适合放在解释 Hugo 行为的段落里，而不是把所有链接堆在文章末尾。

协议相对链接仍然会被识别为外部链接：[协议相对链接](//example.org)。下面这个地址只是为了展示主题的安全处理，不会被当作可以执行的地址：[不安全链接](javascript:alert(1))。

## 留一点节奏

长文不必每一段都配图，也不必每个观点都加粗。读者真正需要的是可以停顿的段落、能回看的标题和不会迷路的链接。

| 写法 | 解决的问题 |
| --- | --- |
| `summary` | 首页不知道要不要打开 |
| 短段落 | 一整面文字没有停顿 |
| 标题锚点 | 回看时找不到位置 |
| 任务清单 | 不清楚还剩什么没有完成 |
